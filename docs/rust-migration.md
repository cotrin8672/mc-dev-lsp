# Complete Rust replacement

The active objective is to replace every currently implemented mc-dev-lsp
capability with Rust, using the ktlsp extension direction. The earlier
`@Mixin`/`@Shadow` slice is a starting point, not the acceptance boundary.

The original JDT LS checkout and its uncommitted changes remain untouched.
Implementation continues in `codex/ktlsp-rust`. No JVM helper, JNI bridge, or
Kotlin subprocess can count as a completed Rust port.

## Authoritative baseline

The current legacy implementation, including uncommitted Kotlin support, was
captured into `build/migration-baseline/current-20261023` before porting. The
snapshot has 526 files and a per-file SHA-256 manifest. Its canonical fingerprint
is `F60A953B01B7E4EDA9D0D6F2A1BA7D1A2E87F8253572F9B9CD6A07EC49D0F3DD`.
The original checkout HEAD was `61cb073373843354f966ff84b646f99763384d5f`;
that commit alone does not include the uncommitted baseline additions.

The detailed source/test inventory is recorded in
`rust-migration-inventory.md`. Historical implementation-status documents are
discovery aids, not proof of parity. Each completed area needs implementation
review, corresponding regression cases, and integration evidence for its public
behavior. Unknown or missing evidence remains incomplete.

## Required distribution and host boundary

The target is a separately distributed extension executable managed by ktlsp
per workspace using a versioned stdio JSON-RPC protocol. ktlsp remains the
authority for Java/Kotlin project models, classpaths, unsaved documents, opaque
identities, and analysis generations. The extension evaluates Minecraft rules
and proposes shared semantic contributions and editor results.

IPC must not block normal analysis or hold a borrowed ReadSession/Workspace
mutex while waiting. Host validation and atomic publication must reject stale
snapshots and withdraw invalidated or crashed-provider contributions. The
existing linked provider remains a migration oracle until the independent
process provides equivalent behavior. Host IPC implementation was requested
from the ktlsp task; at goal start it was not present.

## Every-test migration requirement

The user explicitly requires every existing test case and its fixtures to be ported. Representative regressions, a coverage row, or preserved assertion source alone do not satisfy that requirement. Every legacy test ID needs executable Rust or same-host editor assertions preserving all tested branches, expected data and state transitions. Table consolidation is allowed only when each original case is independently identifiable and actually executed. Pure API golden replay must preserve every captured call and full expected output; cache/concurrency/sequence cases need native stateful tests. JDT-specific adapters need equivalent host-contract tests preserving the original behavior.

The exact-case counts cover all original JUnit domains. Supplemental checks and Lua assertion counts remain separate. Editor workflows, live command/resource/class-byte/SDK capabilities and final distribution remain incomplete.

The machine-readable [complete test ledger](rust-test-migration.json) is derived from the 164 completed legacy JUnit reports: exactly 2,604 unique test IDs, all mapped to a source file. It also records all 171 test source files, 27 Neovim test/support files and 49 fixture sources/resources. Per-domain exact-case evidence is merged only after execution and review; each completed entry names the executable replacement and its full success log.
