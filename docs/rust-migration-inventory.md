# Full Rust replacement inventory

## Baseline and meaning of completion

The authoritative legacy behavior for this migration is the frozen current working tree at `build/migration-baseline/current-20261023`, fingerprint `F60A953B01B7E4EDA9D0D6F2A1BA7D1A2E87F8253572F9B9CD6A07EC49D0F3DD`. This includes the original checkout's uncommitted Kotlin support. It is deliberately broader than the existing `93b20b3` Rust prototype. Historical `docs/10-*` implementation-status claims are not acceptance evidence.

The required final behavior is a separately distributed Rust mc-dev executable integrated with ktlsp through the host's agreed child-process, versioned stdio JSON-RPC extension contract. ktlsp owns project/classpath, unsaved Java/Kotlin documents, facts, IDs, generations and LSP responses. mc-dev owns Minecraft rules and proposes validated shared contributions. No JDT LS process or JVM-based mc-dev helper may remain necessary for the Rust replacement. The host project toolchain is outside the mc-dev runtime. The existing JDTLS branch remains available separately.

Initial Rust evidence is limited to the already verified 13 prototype tests and 49 editor checks for single-target Mixin/Shadow integration. These do **not** prove full Mixin parity, AW/AT parity, MixinExtras parity, project discovery, editor edits, or IPC. All legacy entries below remain pending until an equivalent Rust test and actual single-LSP path are recorded. Pure Rust unit success alone does not prove editor behavior or correct host integration.

Completion requires the same applicable candidates, inserts/imports/snippets, replacement ranges, diagnostics (code, severity, range, message/metadata), navigation/references, code-action edits and project operations for every named test branch below, including invalid/incomplete/ambiguous inputs. Platform-specific adapters can change; their observable behavior cannot silently disappear. An unavailable dependency or host capability is an explicit pending requirement, never permission to narrow the scope.

## Insert, edit, and language fidelity

- Java class completion uses `Type.class` and import edits or FQN. Kotlin uses `Type::class`, reuses existing import aliases, and never inserts Java `.class`. Conflicting names remain qualified; same-package/existing imports do not duplicate. Kotlin imports follow package/file annotations and preserve CRLF and aliases.
- Injection selectors insert `name` for unambiguous AUTO and NEVER, `name(descriptor)return` for ALWAYS and overloaded AUTO. At method target is `Lowner;name(args)return`, field target `Lowner;name:descriptor`; NEW/return/constants have their own formats. Preserve mapping fallback and smart target preferences.
- AW owner uses JVM internal slash form and method/field names plus separate descriptors; AT owner is dotted, method name concatenates descriptor and field insertion omits descriptor. Both apply their configured namespace; a missing mapping cannot silently become a successful remap.
- Completion retains plain-text versus snippet format, placeholders, sort/filter/detail/docs, active-token replacement ranges and all additional edits. Applying an edit is tested on the resulting whole document, including import offsets and multiple edits, not only candidate labels.
- Java escaped strings, Unicode/UTF-16, comments and character literals differ from Kotlin raw strings/interpolation/nested comments. Do not Java-unescape Kotlin raw strings. Arrays/nested constructors/containers/aliases must retain original buffer offsets. Do not parse annotation-like text in comments/strings as code.
- Frozen Kotlin work includes KMixin/KShadow aliases, properties/accessors, companion/static, nullable primitives/boxing, Unit return, arrays/vararg, extension receivers and safe unresolved-generic policies. Existing Kotlin tests below are mandatory, not a future feature.

## Incomplete, error, and ambiguity policies

- Distinguish absent, unavailable and incomplete bytecode/facts/mappings. Unresolved local type/occurrence/extraction is unavailable, not LOCAL_CAPTURE_NOT_FOUND. Missing classpath must not trigger fabricated target members or broad global fallback.
- Ambiguous overloads require explicit descriptors for handler generation/validation where the legacy service does. Ambiguous reference/goto candidates preserve applicable multiple targets; code fixes must not guess an unsafe edit. Invalid/incomplete expression/definition siblings follow their own parser recovery tests.
- Diagnostics and edits respect semantic class/annotation/method scope. Low-confidence handwritten parsing is surfaced and avoids unsafe edits. Kotlin code must never receive Java-only handler generation or false missing-generated-config diagnostics.
- Host uses owned snapshots, opaque evaluation-bound IDs, generation checks, cancellation/timeout/limits. No IPC await while holding Workspace mutex or borrowed ReadSession. Stale/crashed provider contributions withdraw atomically; regular analysis continues. These new transport guarantees supplement legacy parity, not replace it.

## Host API gaps to close for the complete extension

1. Versioned asynchronous provider process lifecycle and snapshot-scoped batched facts/requirements/bindings/diagnostics, stale validation, cancellation, crash withdrawal and arrival refresh.
2. All existing completion contributions: replacement range, snippets, additional import/Definition edits, ordering/filter/docs and debug/readiness; annotation-string completion must join normal host completion rather than a second editor connection.
3. Quickfix/code-action generation and application, including multiple documents/config/AW/AT, source language-aware edits, plus hover contents/ranges. Reuse shared semantic symbols for definition/references/rename; provide scoped string/member bindings and cross-document source search.
4. AW/AT document dispatch, custom filetypes and their definitions/references/completion/diagnostics/actions through the same single LSP. Current Java/Kotlin-only normalized annotation facts cannot represent these files alone.
5. Project/config/classpath/mapping/source-set/generation facts, source-backed unsaved member views, project info/reindex/reload/dump custom operations. Project AtCode/specifier capability discovery also needs a host equivalent.
6. Class bytes/structured bytecode access and hierarchy data sufficient for instruction occurrence matching, live locals/LVT/frame analysis, official MixinExtras expression matching, descriptors and attached source navigation. Signature-only member facts cannot replace bytecode behavior.

JDT reflection/Eclipse compilation units, bindings and source attachments are adapters for these capabilities. OSGi manifest/plugin registration, Eclipse stubs, JVM artifact packaging and nvim-jdtls bundle injection can be retired on the Rust branch once their user behavior is replaced; they are not reasons to drop source resolution, classpath readiness or decompiled/library navigation.
