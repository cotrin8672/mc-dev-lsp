# MixinExtras acceptance evidence

## Completed acceptance audit

The final stable JVM suite passed **2,457 tests, with no failures/errors/skips**, including bundle build/check (`build/test-logs/gradle-tests-20260914-232944065.log`). The five platform fixtures and actual Sodium pass through normal process exit. The primitive class-literal regression and actual navigation adapter/editor movement passed real-JDT E2E (`build/e2e-logs/osgi-e2e-20260914-233305377.log`). Final Luna max reviews identified and resolved the concrete feature and harness defects; parent review and the real-process checks also pass.

Expanded real-JDT acceptance passed all six injector generation/edit/javac cases, Expression member and typed-local completion, Definition/import edits, repeated-ID navigation, Share namespace/type exclusions, Local refs and valid/missing normal callback handling beside Cancellable (`build/e2e-logs/osgi-e2e-20260914-220712604.log`). Unit regressions additionally cover malformed sibling recovery, exact diagnostic ranges, imports and array navigation, actual local bytecode frames and cancellation recovery. Independent reviews of Local/receiver behavior and project readiness were clean.

Real Sodium passes exact method selection, restoration of the entire original source by applying the completion edit, and graceful shutdown. Preserved-workspace startup/warm results were **5,474.1 / 92.2 ms** (`osgi-e2e-20260914-231252728.log`) and **14,322.4 / 119.7 ms** with the final bundle (`233609324`), both with JDT AST/project bindings. The later run includes an approximately eleven-second JDT initialization wait before project import. A simultaneous comparison (`234935759`) resolved ordinary Java hover in **35,808.7 ms**, extension completion in **5,424.8 ms**, and subsequent completion in **60.2 ms**. Startup depends on host readiness, and no universal latency bound is claimed. Annotation-processor lock errors and unclean-workspace warnings were absent. The project-scoped Gradle compatibility setting and all current evidence are recorded in [verification](mixinextras-verification.md).

### Historical investigation notes

- 2026-09-14 active fixes: source-aware Definition types and direct type navigation passed 162 affected tests (`build/test-logs/gradle-tests-20260914-000048841.log`). Typed local definitions now use live method frames for index, ordinal, names and argsOnly, including stores; local/matcher/definition diagnostics/parser checks passed 122 tests with bundle validation (`build/test-logs/gradle-tests-20260914-000453566.log`). Missing ids are retained for targeted diagnostics, while valid sibling bindings remain available. These changes still require the expanded real-editor run and independent review.
- The new transport exposed a real libuv fast-event callback error; scheduling completion on Neovim's main loop fixed it, verified by a real TCP regression (`build/transport-main-loop-test.log`). Subsequent actual Sodium runs still used the ordinary startup fallback (23–39 seconds); warm responses were 33–42 ms. Startup remains unresolved; neither the transport unit tests nor eager activation prove latency improvement. No fixed one-second performance gate is used: the user rejected machine-dependent pass/fail thresholds. Correctness is asserted, timings are compared under matching conditions, and finite runner timeouts protect against hangs.

- Latest real-project baseline (2026-09-13 23:26 JST): after successful full NeoForge artifact preparation, Sodium completion resolved `Gui.renderCameraOverlays` through the actual JDT JavaProject and applied the edit correctly. With preserved JDT data, the first request after server startup took 20,624.8 ms; the next request took 45.1 ms. The finite-timeout run exited 0 (`build/e2e-logs/osgi-e2e-20260913-232528321.log`). The historical `cold` label in that log means first request after startup, not a clean JDT workspace. The test now calls that phase `startup`. Functional correctness passed; startup latency remains unacceptable.

- Editor coverage: the fixture and javac dependency were updated from MixinExtras 0.4.1 to 0.5.5. Expression member completion, Definition/import edits, compilation, identifier navigation and binding reuse passed in real JDT after fixing member navigation and insertion indentation. Independent review found invalid Cancellable fixture signatures: `@Inject` still requires its normal callback parameter in addition to the Sugar parameter. Corrected fixtures, explicit Share namespace/type exclusions, and actual Expression indentation checks all passed (`build/e2e-logs/osgi-e2e-20260913-174839659.log`). The old invalid examples exposed a missing diagnostic that is being fixed; javac alone does not validate injection signatures. The navigation/edit fixes passed 67 affected tests (`build/test-logs/gradle-tests-20260913-172736926.log`); bundle build/check passed (`build/test-logs/gradle-tests-20260913-172905602.log`).
- Real project: Sodium tag `mc1.21.1-0.8.13`, commit `dae4167e7d32a7812556a02d8be73cd5aba459c0`, was obtained under `build/real-projects/sodium` with 652 Java source files. Its actual `:common:compileJava` succeeded (`build/real-projects/logs/osgi-e2e-20260913-172427840.log`). The real editor test requests method completion before any info command, retaining the actual Gradle project and dependencies. First cold import failed to return completion within 120s (`build/e2e-logs/osgi-e2e-20260913-173816183.log`); Gradle was generating NeoForge Minecraft artifacts during project import. This establishes a missing full-project preparation step, not an isolated completion latency. The test runner also reached its 300s outer timeout; its orphan Gradle child was identified through the exited JDT parent's PID and stopped. No successful real-project responsiveness result is claimed yet.
- Responsiveness: investigation found the custom command's global JDT index gate and no supported arbitrary-proposal injection SPI in standard completion. A same-JVM transport is being investigated for implementation and verification. Returning the provisional subset as a falsely complete result is not an acceptable fix.

This inventory is evidence, not a claim of exhaustive IDE parity. The local reference is `build/research-mixinextras-20260828` (MixinExtras 0.5.4). Internal wrapper annotations are implementation details, not user-facing injector families.
